# Chronos Protocol v2

This document defines the wire protocol used by `gateway` and `login-service`.
It reflects the current implementation in this repository.

## 1) Frame format

All numbers are **big-endian**.

| Field        | Type | Size | Description |
|--------------|------|------|-------------|
| magic        | u16  | 2    | Must be `0x4E52` (`'N''R'`) |
| version      | u16  | 2    | Must be `2` |
| opcode       | u16  | 2    | Operation code |
| flags        | u8   | 1    | Bit flags (`0x01` encrypted, `0x02` integrity, `0x04` internal) |
| reserved     | u8   | 1    | Must be `0` |
| payload_len  | u32  | 4    | Payload byte length |
| request_id   | u32  | 4    | Client-generated correlation id |
| session_id   | u64  | 8    | Authenticated session id (`0` before login success) |
| payload      | bytes| N    | Operation payload |

Total header size: **24 bytes**.

## 2) Opcodes

| Name | Value | Direction | Notes |
|------|-------|-----------|-------|
| `OP_LOGIN` | `0x1001` | C<->S | Login request and login result |
| `OP_LOGOUT` | `0x1002` | C->S | Logout authenticated session |
| `OP_SERVER_MESSAGE` | `0x1004` | S->C | Human-readable server message |
| `OP_SERVER_SYNC` | `0x1005` | Internal->S | Internal sync endpoint |
| `OP_INTERNAL_AUTH` | `0x10FF` | Internal->S | Internal service authentication handshake |

Unknown opcodes are rejected.

## 3) Primitive payload types

- `i32`: 4 bytes signed integer (big-endian)
- `i64`: 8 bytes signed integer (big-endian)
- `u8`: 1 byte unsigned integer
- `u64`: 8 bytes unsigned integer (big-endian)
- `utf`: `u16` byte-length prefix + UTF-8 bytes

## 4) Payload definitions

### 4.1 `OP_LOGIN` request (client -> server)

Order:
1. `server_id: i32`
2. `client_id: i32`
3. `username: utf`
4. `password: utf`

Header:
- `session_id` should be `0`
- `request_id` should be unique per request for matching response

### 4.2 `OP_LOGIN` response (server -> client)

Common prefix:
1. `client_id: i32`
2. `status: u8` (`0 = success`, `1 = failed`)

If `status == 1`:
3. `error_text: utf`

If `status == 0`:
3. `user_id: i32`
4. `is_admin: u8` (`0/1`)
5. `active: u8` (`0/1`)
6. `gold_bar: i32`
7. `last_time_login_ms: i64`
8. `last_time_logout_ms: i64`
9. `rewards: utf`
10. `ruby: i32` (currently `0`)
11. `moc_nap: i32` (currently `0`)
12. `server_login: i32`
13. `is_use_ma_bao_ve: i32` (currently `0`)
14. `ma_bao_ve: i32` (currently `0`)
15. `tongnap: i32`
16. `vnd_bar: i32`
17. `session_id_echo: u64` (same as header session id)

Header:
- `request_id`: echoes login request id
- `session_id`: generated by server on success, otherwise `0`

### 4.3 `OP_LOGOUT` request (client -> server)

Order:
1. `user_id: i32`

Header:
- `session_id`: must be valid authenticated session id

### 4.4 `OP_SERVER_MESSAGE` response (server -> client)

Order:
1. `client_id: i32`
2. `text: utf`

Used for maintenance / notification text.

### 4.5 `OP_SERVER_SYNC` request (internal/trusted only)

Order:
1. `server_id: i32`
2. `size: i32`
3. repeated `size` times:
   - `client_id: i32`
   - `user_id: i32`
   - `username: utf`

Header:
- requires prior successful `OP_INTERNAL_AUTH`
- `flags` must NOT contain `FLAG_INTERNAL` for this opcode
- `session_id` is not used for authorization here

### 4.6 `OP_INTERNAL_AUTH` request (gateway/internal service -> login-service)

Order:
1. `internal_psk: utf`

Header:
- `flags` must include `FLAG_INTERNAL` (`0x04`)
- `session_id` can be `0`

Result:
- No payload response is required; if auth fails connection is closed with error.

## 5) Security controls currently active

- Frame validation: `magic`, `version`, known `opcode`, max payload size
- Reserved header byte must be `0`
- Input validation: username/password length constraints at login
- Rate limit per connection:
  - time window: `RATE_LIMIT_WINDOW_MS`
  - max messages: `RATE_LIMIT_MAX_MESSAGES`
- Login brute-force guard per connection:
  - `MAX_LOGIN_ATTEMPTS`
- Session authorization:
  - `OP_LOGOUT` requires valid `session_id`
- Internal authorization:
  - only `OP_INTERNAL_AUTH` may carry `FLAG_INTERNAL`
  - `OP_SERVER_SYNC` requires prior internal auth state on that connection
- Password handling:
  - login query loads `password_hash` and verifies with Argon2
- Integrity modes:
  - `off`: no integrity tag
  - `checksum`: appends 4-byte checksum (debug/dev only)
  - `hmac`: appends 32-byte HMAC-SHA256 tag (recommended for production)
- TLS:
  - optional via server config (`TLS_ENABLED`)

## 6) `.env` configuration used by protocol guard

- `MAX_FRAME_SIZE` (default `65536`)
- `RATE_LIMIT_WINDOW_MS` (default `10000`)
- `RATE_LIMIT_MAX_MESSAGES` (default `120`)
- `MAX_LOGIN_ATTEMPTS` (default `8`)
- `TLS_ENABLED` (default `false`)
- `TLS_CERT_PATH` / `TLS_KEY_PATH`
- `INTEGRITY_MODE` (`off|checksum|hmac`)
- `HMAC_SECRET` (required when `INTEGRITY_MODE=hmac`)
- `INTERNAL_PSK` (required for internal auth)

## 7) Migration checklist for client/gateway

1. Parse/build 24-byte v2 frame header exactly.
2. Use `opcode` as `u16`, big-endian.
3. Generate and echo `request_id` for correlation.
4. Persist `session_id` from successful `OP_LOGIN`; attach for `OP_LOGOUT`.
5. Encode strings as `u16 length + UTF-8 bytes`.
6. For internal services (gateway/game-server), send `OP_INTERNAL_AUTH` first with `FLAG_INTERNAL`.
7. Use sync payload without password field (`client_id`, `user_id`, `username` only).
8. If integrity is enabled, append/verify checksum or HMAC tag as configured.
